Реализовать полностью локальную автокоррекцию для русского, английского
и испанского языков, включая:

1. composing-ввод;

4. панель исправлений;

Модель должна только оценивать заранее сформированные допустимые варианты.
Общий unrestricted `generate(prompt)` в Rune 0.3 запрещён.

==================================================
2. ГЛАВНОЕ АРХИТЕКТУРНОЕ РЕШЕНИЕ
==================================================

Не использовать prompt-based correction:

prompt:
"Исправь этот текст..."

Такой подход запрещён, потому что модель может:

- менять слова;
- менять смысл;
- добавлять текст;
- удалять текст;
- менять стиль;
- возвращать невалидный формат;
- создавать непредсказуемую задержку.

Вместо этого реализовать bounded candidate scoring.

Rune формирует конечный список допустимых вариантов, а model runtime
возвращает только числовые scores.

Пример:

prefix:
"Я хочу добавить"

candidates:
[
  " автокоррекцию",
  " автокорекцию",
  " автокоррекция"
]

result:
[
  { id: 0, sumLogProbability: ..., tokenCount: ... },
  { id: 1, sumLogProbability: ..., tokenCount: ... },
  { id: 2, sumLogProbability: ..., tokenCount: ... }
]

Runtime не должен возвращать generated text.

Для пунктуации:

prefix:
"Я думаю"

candidates:
[
  " это",
  ", это",
  ": это",
  ". Это"
]

Модель только оценивает варианты.

==================================================
4. РАСШИРЕНИЕ RUNTIME: ТОЛЬКО SCORING
==================================================

Текущий LocalModelRuntime имеет:

- load;
- selfTest;
- cancelCurrentOperation;
- unload.

Добавь bounded scoring API.

Предлагаемый контракт:

data class CandidateScoringRequest(
    val prefix: String,
    val candidates: List<ScoringCandidate>,
)

data class ScoringCandidate(
    val id: Int,
    val continuation: String,
)

data class CandidateScore(
    val id: Int,
    val sumLogProbability: Double,
    val scoredTokenCount: Int,
)

sealed interface CandidateScoringResult {
    data class Success(
        val scores: List<CandidateScore>,
        val durationMillis: Long,
    ) : CandidateScoringResult

    data class Failure(
        val code: RuntimeErrorCode,
    ) : CandidateScoringResult
}

interface LocalModelRuntime {
    fun load(modelFile: File): ModelLoadResult
    fun selfTest(): ModelSelfTestResult
    fun scoreCandidates(
        request: CandidateScoringRequest,
    ): CandidateScoringResult
    fun cancelCurrentOperation()
    fun unload()
}

Ограничения native contract:

- максимум 8 candidates;
- candidate id уникален;
- пустой candidate list запрещён;
- prefix и continuations имеют жёсткий byte/token limit;
- общий контекст не превышает runtime context;
- никакой generated string не возвращается;
- только числовые scores;
- UTF-8 обязательно проверяется;
- cancellation работает во время tokenize/decode/scoring;
- любой invalid request возвращает стабильный error code;
- JNI exceptions не покидают native boundary;
- model/context lifetime остаётся RAII;
- глобальные model/context pointers запрещены;
- logger llama.cpp остаётся отключённым.

Добавь error codes:

- INVALID_REQUEST;
- CONTEXT_TOO_LONG;
- TOO_MANY_CANDIDATES;
- SCORING_FAILED.

Scoring:

1. Токенизируй полные варианты `prefix + continuation`.
2. Не предполагай, что `tokenize(prefix) + tokenize(continuation)` совпадает
   с tokenization полной строки.
3. Найди общий token prefix полных вариантов.
4. Оцени log probability только divergent continuation span.
5. Используй numerically stable log-softmax.
6. Возвращай:
   - сумму log probabilities;
   - количество реально оценённых токенов.
7. Length normalization выполняется в Kotlin ranker, а не прячется внутри JNI.
8. Не добавляй BOS повторно для каждого continuation.
9. Не включай EOS в score, если это явно не обосновано evaluation.

Сначала сделай корректную реализацию.

Оптимизация shared-prefix через sequence IDs и KV copy допускается только
после теста эквивалентности с простой реализацией. Оптимизированный и простой
пути должны давать scores с документированным числовым tolerance.

Native tests должны проверять:

- identical candidates дают одинаковый score;
- ожидаемый token получает более высокий score на synthetic logits;
- length normalization не выполняется в native;
- Unicode RU/ES проходит без повреждения;
- invalid UTF-8 блокируется;
- cancellation;
- context overflow;
- candidate count limit;
- repeated score/load/unload lifecycle;
- отсутствие output text.

Не добавляй unrestricted `generate()`.

5. PRIVATE MODEL INFERENCE SERVICE
==================================================

Не загружай 396 MB model непосредственно в RuneInputMethodService process.

Создай отдельный private bound service:

ModelInferenceService

Manifest:

- android:exported="false";
- android:process=":model_runtime";
- без intent-filter;
- без foreground service;
- без отдельного permission;
- доступен только тому же приложению.

Не переиспользуй JobService как interactive inference API.

ModelInstallJobService сохраняет ответственность только за:

- verify;
- install;
- self-test;
- activate.

ModelInferenceService отвечает только за:

- разрешение active model pointer;
- lazy load active model;
- candidate scoring;
- request cancellation;
- unload;
- binder death;
- memory pressure.

Создай узкий AIDL contract.

Пример:

interface IModelScoringService {
    void scoreCandidates(
        long sessionId,
        long requestId,
        String prefix,
        in List<String> candidates,
        IModelScoringCallback callback
    );

    void cancel(long sessionId, long requestId);
}

oneway interface IModelScoringCallback {
    void onSuccess(
        long sessionId,
        long requestId,
        in double[] sumLogProbabilities,
        in int[] tokenCounts
    );

    void onFailure(
        long sessionId,
        long requestId,
        int errorCode
    );
}

Фактический AIDL можно скорректировать, но он должен:

- быть bounded;
- иметь request/session IDs;
- не возвращать generated text;
- поддерживать cancel;
- не содержать Bundle с произвольными полями;
- не логировать payload;
- не сохранять payload;
- не передавать model path наружу.

Service lifecycle:

- загружать active model лениво;
- не блокировать main thread;
- иметь один serial inference worker;
- держать максимум один активный запрос на IME session;
- отменять предыдущий запрос при появлении нового;
- выгружать модель при завершении idle timeout;
- выгружать при критическом memory pressure;
- корректно переживать process kill;
- при binder death возвращать client в unavailable state;
- автоматически перепривязываться только при активной обычной text session;
- не привязываться в sensitive field;
- не привязываться в TYPE_NULL;
- не привязываться, если Smart Typing выключен.

IME никогда не ждёт Binder synchronously.

Любая модельная операция асинхронна.

Если service:

- загружается;
- умер;
- занят;
- не имеет модели;
- вернул ошибку;

Rune продолжает печатать без задержки через deterministic fallback.

==================================================
8. COMPOSING SEGMENT С УПРАВЛЯЕМОЙ ГРАНИЦЕЙ
==================================================

Для поддержки пунктуации не держи только слово.

Используй composition из:

- leading boundary;
- текущего слова.

Пример:

ComposingSegment(
    leadingBoundary = " ",
    typedWord = "это",
)

В editor composing region находится:

" это"

Если contextual punctuation предлагает запятую:

leadingBoundary:
" " → ", "

composing text:
" это" → ", это"

Это позволяет исправить:

"Я думаю это"

в:

"Я думаю, это"

не удаляя и не перечитывая уже committed текст.

Обязательные состояния:

- Idle;
- PendingBoundary;
- ComposingWord;
- CandidateSelected;
- AutoCorrectionCommitted;
- Cancelled/Invalidated.

Поведение:

1. Первая буква начинает composing word.
2. Следующие буквы обновляют `setComposingText`.
3. Space:
   - выбирает correction decision;
   - завершает слово;
   - начинает pending leading boundary `" "`.
4. Следующая буква превращает pending boundary в `" <word>"`.
5. Пунктуационный scorer может изменить только leading boundary текущего
   composing segment.
6. Enter/language switch/cursor move/symbol layer:
   - безопасно завершает composition;
   - отменяет scoring request;
   - очищает candidates.
7. Selection:
   - завершает или отменяет composition согласно текущему editor state;
   - новый ввод заменяет выделение.
8. TYPE_NULL:
   - composing полностью отключён;
   - сохраняется текущий raw key event путь.
9. SENSITIVE:
   - composing, context, candidates и model client отключены;
   - сохраняется plain commit.
10. Если `setComposingText` возвращает false:
    - не падать;
    - отключить Smart Typing только для текущей editor session;
    - перейти на существующий plain commit;
    - не повторять попытку на каждой клавише.

Не делай composing region длиной во всё предложение.

==================================================
9. SESSION CONTEXT И PRIVACY
==================================================

Для model ranking хранить только эфемерный контекст текущей Rune session.

SessionTextContext:

- только RAM;
- не SharedPreferences;
- не файл;
- не database;
- не backup;
- не analytics;
- не exception message;
- не Logcat;
- не diagnostics;
- не trace name;
- не delivery subsystem.

Источник context:

- только текст, введённый через Rune после начала текущей editor session;
- не читать весь editor;
- не читать экран;
- не использовать Accessibility;
- не запрашивать абзац через getTextBeforeCursor после каждой буквы.

Ограничение:

- bounded по UTF-16/code points;
- bounded по model tokens;
- старый контекст удаляется с начала;
- граница не должна разрезать grapheme cluster;
- при внешнем перемещении курсора context invalidated;
- при выделении context invalidated;
- при неизвестном editor mutation context invalidated;
- при завершении input context уничтожается;
- при sensitive field context вообще не создаётся.

Model process получает context только для текущего bounded request и не хранит
его после результата/cancel.

Обнови privacy documentation честно:

- текст теперь передаётся через Binder в приватный процесс того же приложения;
- текст не передаётся в сеть;
- текст не сохраняется;
- модель работает локально;
- sensitive fields не вызывают Binder scoring.

==================================================
10. EXTERNAL SELECTION И STALE STATE
==================================================

Используй `onUpdateSelection` для проверки ownership composing region.

Различай:

- ожидаемое обновление после собственного setComposingText;
- внешнее движение курсора;
- внешнюю замену текста;
- смену selection;
- потерю composing region;
- restart того же editor;
- новый editor.

Каждый async model request содержит:

- sessionId;
- revision;
- requestId;
- exact candidate IDs.

Result применяется только если:

- sessionId совпадает;
- revision совпадает;
- requestId всё ещё активен;
- composing text не изменился;
- editor session не завершена;
- inputPolicy всё ещё NORMAL.

Любой stale result просто уничтожается.

Запрещено применять correction после того, как пользователь уже нажал Space,
Enter, сменил язык или отредактировал слово.

Никаких retroactive corrections с визуальным прыжком текста.

11. CANDIDATE STRIP
==================================================

Текущий RuneKeyboardView вызывает `removeAllViews()` при перестроении клавиш.

Перед candidate strip раздели:

RuneKeyboardView
├── CandidateStripView

    └── keyboard rows

- закрывать popup;
- сбрасывать активный touch;
- менять Shift;
- менять язык;
- запускать полный layout rebuild.

Candidate strip:

- максимум 3 основных видимых кандидата на cover screen;
- горизонтальная прокрутка только если реально нужна;

- tap на исходное слово запрещает auto-replace для текущего слова;

  реализуется без personalization subsystem;
- никаких next-word candidates;
- никаких phrase suggestions;
- никаких AI sparkle/icons;
- никаких network states внутри клавиатуры;
- loading модели не должен показывать spinner на каждый символ.

Candidate types:

sealed interface CandidateUiItem {
    data class Original(...)
    data class Correction(...)
    data class Punctuation(...)
}

Candidate strip полностью скрывается:

- в password;
- при NO_PERSONALIZED_LEARNING;
- в TYPE_NULL;
- email;
- URI;
- phone;
- number;
- date/time;
- при выключенном Smart Typing.

Добавь accessibility:

- content description;
- selected state;
- TalkBack action;

==================================================
13. CANDIDATE GENERATION
==================================================

Candidate generation выполняется без модели.

Используй:

- exact lexicon lookup;
- weighted Damerau-Levenshtein;
- insertion;
- deletion;
- substitution;
- transposition;
- repeated character;
- static keyboard adjacency;
- word frequency rank;
- active language prior;
- script detection;
- case pattern.

Не используй фактическую touch trajectory.
Glide typing отсутствует и не должен появиться.

Language routing:

- Cyrillic → RU;
- `ñ`, испанские accents → ES;
- обычная Latin строка → active EN/ES с ограниченным fallback;
- активная раскладка является сильным prior, но не абсолютной границей;
- mixed-script token не auto-correct;
- mixed-language предложение допустимо.

Protected token policy:

Не auto-correct, если token:

- содержит `/`, `\`, `@`, `_`;
- похож на URL/email/path;
- содержит цифры и буквы;
- camelCase;
- snake_case;
- kebab-case technical token;
- ALL_CAPS длиной больше одной буквы;
- содержит unusual symbols;
- UUID;
- IP;
- semantic version;
- code identifier;
- shell fragment;
- слишком длинный;
- смешивает scripts.

Case preservation:

- lowercase → lowercase;
- Title Case → Title Case;
- UPPERCASE → UPPERCASE;
- mixed case → suggestion only либо no correction.

Valid dictionary word по умолчанию не заменяется другим valid word.

Например:

- `все` не превращать молча в `всё`;
- `esta` не превращать молча в `está`;
- `form` не превращать в `from`.

Такие случаи допускаются только как contextual suggestions после отдельной
калибровки, но не как auto-correct в 0.3.

Candidate set:

- original;
- максимум 7 generated alternatives;
- deterministic order до model ranking;
- никакого unbounded search;
- никакого полного прохода по lexicon на каждую букву.

==================================================
14. RANKING И CONFIDENCE
==================================================

CandidateRanker объединяет:

- edit cost;
- keyboard adjacency cost;
- transposition bonus;
- frequency rank;
- language prior;
- case compatibility;
- word length;
- model average log probability;
- model margin;
- protected-token policy.

Native runtime возвращает raw:

- sumLogProbability;
- tokenCount.

Kotlin ranker вычисляет normalized model score.

Не превращай model score в единственный критерий.

CorrectionDecision:

sealed interface CorrectionDecision {
    data class AutoReplace(val candidate: CorrectionCandidate) : CorrectionDecision
    data class Suggest(val candidates: List<CorrectionCandidate>) : CorrectionDecision
    data object KeepOriginal : CorrectionDecision
}

AutoReplace разрешён только если:

- input policy NORMAL;
- mode TEXT;
- original отсутствует в lexicon либо имеет доказанную typo policy;
- edit distance в допустимой границе;
- top candidate существенно лучше второго;
- top candidate существенно лучше original;
- confidence bucket прошёл holdout gate;
- результат относится к текущей revision;
- user не выбрал original;
- candidate доступен до word boundary.

Не задерживать Space ради модели.

При Space/punctuation/Enter:

- использовать последний актуальный result;
- если result не готов, использовать deterministic decision;
- если deterministic decision недостаточно уверен, сохранить original;
- поздний model result игнорировать.

==================================================
15. AUTOCORRECTION TRANSACTION И UNDO
==================================================

Любая автоматическая замена должна быть транзакцией:

data class AutoCorrectionEdit(
    val original: String,
    val replacement: String,
    val committedBoundary: String,
    val sessionId: Long,
    val revision: Long,
)

Пример:

typed:
"автокрекция"

Space:

"автокоррекция "

Первый Backspace сразу после auto-correction:

1. удалить replacement и boundary одним batch edit;
2. восстановить original как composing text;
3. показать candidates;
4. не сохранять rejection пока personalization отсутствует;
5. не выполнить одновременно обычный Backspace.

После любого другого text action Undo transaction закрывается.

Объедини существующий double-space undo и autocorrection undo в одну
typing-owned концепцию:

sealed interface UndoableTextEdit {
    data class DoubleSpacePeriod(...)
    data class AutoCorrection(...)
    data class MechanicalPunctuation(...)
}

`pendingDoubleSpaceUndo` не должен продолжать жить отдельным независимым
механизмом в KeyboardState после миграции.

Миграция должна быть отдельным тестируемым commit.

==================================================
16. MECHANICAL PUNCTUATION
==================================================

MechanicalPunctuationEngine работает детерминированно и без модели.

Автоматически исправлять:

- пробел перед `, . ? ! : ;`;
- отсутствие пробела после `, : ;`, если далее начинается обычное слово;
- отсутствие пробела после `. ? !`, если далее начинается новое предложение;
- повтор обычных пробелов;
- случайный одиночный duplicate punctuation;
- капитализацию после sentence boundary через существующий caps mechanism.

Примеры:

"Привет ,как дела"
→ "Привет, как дела"

"Хорошо.завтра отправлю"
→ "Хорошо. Завтра отправлю"

"текст  текст"
→ "текст текст"

Обязательные exclusions:

- `3.14`;
- locale decimal `1,5`;
- `12:30`;
- `1.2.3`;
- `example.com`;
- email;
- URL;
- IPv4;
- IPv6;
- path;
- code;
- `...`;
- `?!`;
- `!?`;
- emoji sequences;
- closing quotes/brackets;
- opening quotes/brackets;
- EMAIL/URI/NUMBER/PHONE/DATE_TIME;
- TYPE_NULL;
- SENSITIVE.

Не удаляй многоточие.
Не запрещай пользователю намеренно ввести `?!`.
Не нормализуй кавычки без отдельной команды.
Не вставляй финальную точку перед SEND молча.

Mechanical edit также должен иметь immediate Undo.

==================================================
17. CONTEXTUAL PUNCTUATION
==================================================

Contextual punctuation использует тот же bounded candidate scorer.

В 0.3 модель может менять только `leadingBoundary` текущего composing segment.

Допустимые варианты по умолчанию:

- `" "`;
- `", "`;
- `": "`;
- `"; "`;
- `". "`;
- `"? "`;
- `"! "`.

Набор вариантов дополнительно ограничивается rule engine и языком.

Пример:

Committed context:
"Я думаю"

Current composing word:
"это"

Candidates:
- `" это"`;
- `", это"`;
- `": это"`;
- `". Это"`.

В 0.3 contextual punctuation:

- показывается как suggestion;
- не применяется автоматически по умолчанию;
- не изменяет слова;
- не изменяет текст позади committed boundary;
- не переставляет слова;
- не переписывает предложение;
- не вставляет несколько знаков за один result;
- не применяется после stale result;
- не работает в sensitive и non-text modes.

Не пытайся исправлять все запятые во всём предложении.

Каждая boundary рассматривается тогда, когда следующий word ещё находится
в composing segment. Это даёт достаточно прав для изменения текущей границы
без retroactive text rewrite.

Испанские открывающие `¿` и `¡` нельзя надёжно вставить задним числом этим
механизмом. В Rune 0.3 они остаются manual long-press symbols.
Не создавай опасный whole-sentence rewrite ради них.

26. DEFINITION OF DONE
==================================================

Rune Smart Typing 0.3 готова только если:

- текущее слово использует composing;
- обычный ввод не ждёт модель;
- RU/EN/ES candidate generation работает локально;
- original всегда доступен;
- high-confidence spelling correction проходит holdout precision gate;
- ambiguous corrections только предлагаются;
- Backspace мгновенно возвращает original;
- double-space undo не конфликтует с autocorrection undo;
- mechanical punctuation работает автоматически;
- contextual punctuation предлагается через bounded scoring;
- contextual punctuation не меняет слова;
- unrestricted generate отсутствует;
- late results никогда не меняют committed text;
- model process crash не роняет IME;
- Rune работает без модели;
- sensitive fields не используют composing/scoring/context;
- пользовательский текст не логируется и не сохраняется;
- IME не выполняет network или native runtime calls напрямую;
- model service private и non-exported;
- candidate update не перестраивает клавиши;
- API 26 instrumentation зелёный;
- API 37 instrumentation зелёный;
- physical Fold acceptance пройден;
- performance report содержит реальные measurements;
- model quality report содержит полный holdout result;
- README и ARCHITECTURE соответствуют коду;
- версия обновлена до 0.3.0;
- CI полностью зелёный.
