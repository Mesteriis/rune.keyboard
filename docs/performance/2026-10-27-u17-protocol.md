# U17 — packed asset startup measurement protocol

The acceptance receipt is
`docs/acceptance/2026-10-27-u17-profile-startup.md`. Raw traces, UI snapshots,
memory snapshots and analysis results remain in ignored
`build/perf/review-u17-20261027/`. The device is addressed explicitly through ADB;
the phone window is coordinated before changing its selected IME.

## Builds and inputs

Use an independent disposable checkout at `dcba8ac` for the pre-U17 baseline.
Apply the adjacent `2026-10-27-u17-baseline-trace.patch`: it adds the same four
load/ready markers to the two Android resource owners, without changing loading
algorithms or the native recipe. Preserve the patch and source identities.
The candidate uses the committed U17 readers and language lifecycle. Build each:

```sh
./gradlew :app:assembleProfile :app:privacyGateProfile
```

`profile` uses release R8/resource shrinking, debug signing and a separate
`.profile` ID, with `debuggable=false` and shell profiling. The experiment verifies
the installed package rejects `run-as`, verifies all 69 APK assets match between
builds, and requests `cmd package compile -m speed -f` with a successful result.
The fixed trace processor is Perfetto v58.2-add693d8b; its wrapper, native binary
and public artifact SHA are bound in the receipt.

Build a separate QA host with `:app:assembleDebug -PruneNativeQualification=true`.
Its `.qualification` ImeQaActivity runs in `:qa_editor`, keeping editor and measured
IME in different processes. Use the public empty plain-text field. Main Rune's
personal data and preferences are outside the profile/host packages.
The measured profile package starts with task-owned private state, without a
downloaded GGUF or imported personal profile; language configuration is reused
between the paired builds.

## Run conditions

Save the exact default/enabled IME settings and show_ime_with_hard_keyboard value;
restore all three after the series with safely quoted remote arguments. Verify
current user 0 and validate package inventories from `pm list packages --user 0`:
only package lines establish presence/absence. The phone must already be unlocked.
Temporary packages must have recorded task ownership before installation/removal.

Configure the profile app through its language UI: RU-only or EN-only. Enable the
desired language before disabling the others and verify the resulting checkbox
state. For each sample, select an existing fallback IME, force-stop the profile
package and verify its PID is absent. Open the QA host's empty field, verify its
package/resource ID/focus and tap that observed field. Start capture and select
the profile IME. This starts an actual new service process, independently of the
settings activity used for configuration.

Take dumpsys meminfo for the profile package approximately five seconds after
selection. Finish the observation at seven seconds; native Perfetto capture has
an eight-second TTL. Force-stop between samples. The filesystem cache is left
intact after installation/configuration and previous runs. Series order is
baseline RU × 5, candidate RU × 5, candidate EN-only × 5, baseline EN-only × 5.
Include every successful predefined sample; preserve capture failures separately.

## Capture and analysis

Fold uses native Perfetto with this configuration and a unique task-owned output
file under `/data/misc/perfetto-traces/`, pulled and removed after completion:

```text
buffers { size_kb: 16384 fill_policy: RING_BUFFER }
data_sources { config {
  name: "linux.ftrace"
  ftrace_config {
    atrace_categories: "am"
    atrace_apps: "io.github.mesteriis.rune.keyboard.profile"
  }
} }
data_sources { config { name: "linux.process_stats" } }
duration_ms: 8000
```

The dedicated API 26/2 GiB emulator records `atrace --async_start -b 16384 -a
io.github.mesteriis.rune.keyboard.profile am app` and `--async_stop`. Its ftrace
text is imported into the same local Perfetto trace processor. Both forms use:

```sql
SELECT ts, dur, name FROM slice
WHERE name GLOB 'Rune#*'
   OR name = 'Start proc: io.github.mesteriis.rune.keyboard.profile'
ORDER BY ts;
```

Require exactly one Start proc marker per sample. Measure ready times from that
framework process-creation marker to dictionaryReady/contextualReady, and load
durations from their corresponding load sections. Both baseline configurations
and candidate RU require exactly one of each resource marker; candidate EN-only
requires none. Record PSS from TOTAL/TOTAL PSS and APK mapping PSS separately.
Query nonzero error/data_loss importer statistics for every trace as well.

Report medians and ranges for five samples per condition. These are process-cold
resource-start measurements with a five-second PSS snapshot, not a live-object
heap census. Keyboard interaction/frame budgets have their own review cards.
The official [Perfetto CLI analysis guide](https://perfetto.dev/docs/getting-started/command-line-analysis)
describes local SQL execution; the receipt pins the actual tool used here.
