# Локальная диагностика debug-сборки

Дополнение по явному запросу владельца от 6 сентября 2026 года. Два независимых
переключателя находятся в настройках debug-сборки. В release и profile их нет.
Оба по умолчанию выключены; обычная установка ничего не записывает.

«Сбор диагностической информации» сохраняет технические события и причины
решений: готовность кандидатов, принятие или отклонение результата, автоматическую
или ручную правку, отдельное нажатие Backspace, Undo и ответ редактора. В этой записи нет слов, символов клавиш,
контекста, хешей текста, названий приложений или сообщений исключений.

«Запись набираемого текста» включается только после двух отдельных подтверждений.
Она дополнительно сохраняет введённый через Rune текст, собственный ограниченный
контекст, исходное слово, варианты и результат. Это предназначено для разбора
ошибок автозамены. Текст из редактора не считывается. Уже набранный до включения
буфер не записывается: после согласия начните новую сессию ввода, например заново
откройте поле. Изменение одного переключателя не включает второй.

Пароли, поля с `NO_PERSONALIZED_LEARNING`, email/URL, числовые и прочие поля,
не поддерживающие Smart Typing, исключены из обоих потоков записи. При потере
собственной сессии запись приостанавливается; текст разных сессий не склеивается.
Смена языка или слоя закрывает текущий диагностический сегмент. При следующем
допустимом буквенном вводе Rune начинает новый сегмент с тем же согласием; разные
языки и режимы не склеиваются в одну последовательность.
В обычном текстовом поле пользователь может сам набрать личные данные, и при
включённой записи они будут частью локального журнала.

Файлы JSONL хранятся в приватном каталоге приложения
`no_backup/typing-diagnostics`: до 1 МиБ технических событий и до 4 МиБ текста,
по четыре циклических файла на поток. Очередь ограничена 256 событиями и 512 КиБ,
одна запись — 8 КиБ. Переполнение может пропустить события. Журнал предназначен
для диагностики, а не для восстановления всего набранного текста.

`tools/typing_diagnostics_analyzer.py` читает схемы 1–3 и ротации, сводит
окончательные исходы правок, считает явно записанные Backspace и восстанавливает
ограниченные пары «слово до/после» только при наличии явных Backspace и повторного
ввода. Схема 3 отдельно записывает завершённость, число просмотренных состояний и
проверенных терминалов быстрого локального поиска; это свидетельство не смешивается
с итогом расширенного поиска.
Журналы, созданные до появления события `BACKSPACE`, честно показывают ноль;
косвенные разрывы ревизий не выдаются за точное число нажатий.

Выключение прекращает приём новых записей и отменяет ожидающие. Завершение
отключения показывается после окончания уже начатой операции записи. Удаление
отключает оба вида сбора и удаляет управляемые файлы; завершение удаления также
подтверждается после операции в фоне.

Выгрузка каждого потока выполняется отдельно по явному нажатию через системный
выбор файла. Rune самостоятельно никуда журнал не отправляет. Выбранный файловый
провайдер может синхронизировать файл с облаком; выгруженные копии нужно удалять
отдельно. Удаление журналов в Rune отменяет устаревший запрос выгрузки.

Диагностика не использует Logcat, сеть, модельный IPC, модельное хранилище или
новые разрешения. Исходные ограничения приватности продолжают действовать для
release/profile и для debug без этого явного согласия. Проверки границ сравнивают
каждый source set, классы до R8, итоговый DEX с mapping и manifest; тесты проверяют
само согласие, границы сессий и содержимое записей.

Фактический статус реализации и проверок находится в
[журнале 0.3](plans/2026-09-02-smart-typing-progress.md).
