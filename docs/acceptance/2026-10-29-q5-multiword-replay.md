# Q5: disclosed multiword controller replay

The current-product JVM replay now has a separate opt-in Russian phrase mode. Each two-to-six-word phrase uses one controller and one in-memory editor session; every word is typed, sent through the staged local candidate/recovery cascade and committed by its boundary before the next word. The observer retains the editor text before and after each boundary, distinguishes prefix changes, case-only and automatic edits, records grammar/noun revision attempts and checks immediate Undo when the final boundary applied a correction. This is a JVM controller/editor simulation, not a live Android IME timing or external-model test.

Six previously disclosed regression phrases cover infinitive and noun-case corrections, continuation after a corrected word, exact Undo at a final correction, and two unchanged controls. Two fresh runs produced byte-identical observations: four boundary changes, four automatic edits, zero prefix changes, zero case-only changes and two exact Undo checks with zero failures. The harness confirms the relevant revision paths were attempted. No external model calls were made. The [receipt](2026-10-29-q5-multiword-replay-evidence.json) binds the source, fixture, assets, toolchain files and both registry snapshots.

Twenty distinct typed/corrected stage contexts are registered as disclosed in both durable ledgers, with hash-bound fixture/generator identities. Tests reject reuse through both registries and refuse omitted or altered registration, corrupt stage observations, missing revision paths and incorrect Undo. The CI workflow runs the phrase test and replay and retains its output. These six cases are not an independent corpus, a proofread control baseline, a Wilson estimate or full Q5 acceptance. Complete public corpus provenance, broader phrase/revision evaluation and real-device evidence remain open.

The existing two-pass token replay passed all 2,160 multilingual and 12,000 historical rows with unchanged frozen projections after the Kotlin harness change; that run preceded the additional phrase registry entries. The current phrase run validates those entries and snapshots both final ledgers. The separate existing real Android suite was running concurrently, so no latency claim is made.
