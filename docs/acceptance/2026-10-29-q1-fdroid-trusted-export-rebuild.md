# Q1: rebuild exported source against trusted Git

The [F-Droid source archive](2026-10-29-q1-fdroid-source-export.md), SHA-256 `5777647d0ee4a6cb8f4688ee3ae932a76b954cc1ea0e3b83f41e7ae8d6fcfbbb`, was rebuilt without weakening the mandatory clean-source gate. A fresh disposable clone was checked out at the trusted original commit `00936a6a58726037c8d924f9f90a211320941f7a`, including its pinned submodule. The archive hash was verified, every member was checked to be a regular file or directory beneath its expected root with no traversal or Git metadata, and the archive was extracted separately. Its prepared files were then overlaid onto the disposable checkout while preserving that checkout's Git metadata.

The real prepared-source checker accepted exactly 11 approved changes and one pinned submodule. The actual offline `assembleRelease` with `runePreparedSource=fdroidserver-2.4.5` completed, including release source tests and the qualification/source gates. The unsigned APK was byte-identical to the F-Droid APK from the archive-producing build, SHA-256 `183b9808136ca3897842e6cb935928b62548969de4d47167dd48e90261efdbc4` (180,122,901 bytes). A deliberate unrelated tracked-source mutation was refused as `RELEASE_PREPARED_SOURCE_DELTA`; restoring it made the check pass again. Build log and mutation result are retained under `build/q1-trusted-export-rebuild-20261029/`.

The two builds used the same host, installed SDK/CMake and existing Gradle cache; this is not independent build-server reproducibility. The archived source alone still cannot prove its own identity: the Git commit and archive digest must come from a trusted external source, and the archive must be checked before extraction. No new unsigned or signed APK was installed or published. The test ran concurrently with a disposable emulator, so no timing claim is made.
