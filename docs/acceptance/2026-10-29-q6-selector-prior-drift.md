# Q6: prior-input drift checks for selector collectors

The additional-epoch and word-ranking selectors read previous public data graphs to exclude prior articles, contexts and text. They now snapshot every consumed prior data manifest, observation binding and row/text file before reading, and recheck the snapshot after the final registry gate and before writing output. Their receipts retain respectively 8 and 16 prior input hashes. Retrieval retains its 25-input check through the same shared implementation. The common refinement helper is also included in selector source input snapshots. Historical reproduction does not take these independent-mode snapshots and keeps its original row schema.

Actual diagnostics exercised both collectors on the pinned public source and isolated historical fixture workspaces. The initial/final registry gates and the separate unchecked-text refusal were deliberately intercepted only to reach the final point; they remain active in normal execution. Each diagnostic modified a prior refinement row file at the final gate. Both collectors raised `JOINT_PUBLIC_INPUT_DRIFT` and created no output. This proves that scoped refusal, not independent corpus qualification. The guard test covers 8/16/25 input snapshots and mutations to observation, row and text files.

Fresh historical runs for word-ranking and additional epoch each reproduced all seven JSONL files byte for byte against retained earlier reproductions. The fixture and independent-holdout test suites passed 25 tests with no skips. Registry completeness, separate training-text independence, source provenance and fresh qualification remain open. No APK, model or device was changed.
