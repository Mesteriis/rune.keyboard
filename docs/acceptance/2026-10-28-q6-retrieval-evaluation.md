# Q6 manual retrieval evaluation binding and exporter repair

The old manual-retrieval evaluator could describe a selected corpus as fresh
without consulting the permanent registries, and only wrote scorer hashes after
numerical work. The maintained CLI now gates before optional scorer imports or
export reads, including under `python -O`. Disclosed diagnostics and former fresh
tests require `--historical-reproduction`; report roles are explicit and both
`independentQualification` and `productionQualified` remain false. This observer
measures manual suggestions; it does not approve an automatic correction policy.

The receipt binds every declared export file/source, mandatory consumed members,
source-freeze equality, both scorer weights, code and registries. Real external
compiler/SDK files are hashed as data; no receipt command is executed. Supplied
manifest/selection edges, every declared corpus file, public source lock and
article identities are bound too. Typed error/control counts, actual original
tokens, manual-pool bounds, search counters and finite nonnegative host timings
are validated. Input/source/registry drift is checked before exclusive output;
a change during actual numerical scoring cannot leave a report.

The original exporter also failed compilation on current correction code:
experiment-policy dependencies were missing. Its source selection now reuses
the morphology exporter's existing pure candidate dependency filter. The exact
old evaluator/exporter bytes are retained in the frozen-source manifest.
CI now runs `retrieval_export_smoke.py` after Gradle/morphology export and uploads
actual compiler/generator receipts. Hosted workflow execution remains unverified;
no push or dispatch was performed.

Actual local evidence:

- Original exporter: exit 1, unresolved experiment-policy references; raw failure
  and compile logs retained. Fixed exporter and the CI entry point both compile
  and execute four original disclosed word rows. Their candidate/index/local-
  policy outputs match exactly after removing only three host timing fields.
- Two typo inputs have six manual candidates versus three baseline candidates;
  absent proposals/gold remain counted. The separate correct control is retained.
- Seven new stdlib tests and all six original retrieval tests pass. Original
  test method bodies/assertions are retained; class setup explicitly loads the
  optional scorers for the existing mocks.
- Full stdlib: 119 modules / 638 tests, zero failures/errors/skips.
- Full scientific: 23 modules / 76 tests, zero failures/errors; one explicit MLX
  environment skip. CI tools: 41 passing tests; packaged provenance: 12 passing.
- The permanent numerical driver uses actual current JVM proposals and real
  packaged RET2/REC2 scoring. It binds 92 files, rejects all 90 isolated source/
  export mutations, refuses mid-scoring drift and a second write. Two actual
  packaged models are never mutated by the smoke; mutation of both is covered
  with isolated synthetic model bytes in the stdlib snapshot test.
- All packaged assets, frozen Kotlin identity and parity bytes are unchanged.
  The full sealed report, private native receipts/logs and two-projection hashes
  are retained under ignored `build/`.

The portable capture contains only four already disclosed original word rows,
current manual-retrieval observations and project source hashes. Its source
attribution, licenses and permanent article/context exclusions are inherited
from the verified word fixture. The derivative receipt is explicitly marked;
external compiler/runtime metadata is retained in the actual local export and
is not fabricated for the portable numerical fixture. Host timing excludes
model scoring/editor/render/loading and proves no Android latency budget.

This proves current tooling execution and input binding, not original retrieval
experiment reproduction, unseen natural quality, complete historical transitive
provenance or Q6 closure. Other evaluation/calibration/promotion entry points and
the original historical/family/fresh-data gaps remain in scope. No APK changed.
See [machine-readable evidence](2026-10-28-q6-retrieval-evaluation-evidence.json).

## Edit-count validation follow-up (2026-11-09)

The shared word/retrieval evaluation input validator now requires each typo's
`errorCount` to equal the generator's optimal-string-alignment distance,
including adjacent transpositions. Its existing checks still require a zero-edit
control to equal its target. Both evaluation receipts bind the source of the
distance function and recheck it for drift. This protects the per-edit-count
metric denominators; it does not verify that the target is contextually correct
or that a typo is natural or independently qualified.

The validator accepted all 1,800 disclosed historical retrieval rows and all
9,000 verified archived word-ranking rows (6,000 train, 1,200 dev, 1,800 test).
Regression tests reject a one-edit retrieval row relabelled as two edits and a
word row relabelled from two edits to one; an adjacent transposition is accepted
as one edit. The focused word receipt, retrieval receipt and word data suites
passed 9, 7 and 3 tests. The six retrieval scorer tests passed with the pinned
NumPy 2.2.6 and CatBoost 1.2.8 in a temporary `uv --no-cache` environment.
An initial attempt with the default Python failed because NumPy was absent.
The full stdlib inventory passed 183 modules and 909 tests with zero failures,
errors or skips. Temporary test outputs were removed. No model, APK, phone or
prior receipt was changed.
