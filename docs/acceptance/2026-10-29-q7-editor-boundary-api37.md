# Q7: editor boundary instrumentation on API 37

The fresh API 37 general suite reported a failure in `distinctEditorResetsManualShiftAndSymbolsThroughBinder`: immediately after a second focus operation on the multiline field, the test did not observe the symbols-layer return key. The original method failed again on a separate clean API 37 emulator. Waiting five seconds did not fix it. In a diagnostic variant, Rune still reported that it served the multiline editor before and after the tap, while a temporary listener observer counted zero delivered `ToggleSymbols` actions. A failure screenshot also showed an Android text-selection toolbar over the keyboard; the evidence does not establish that the toolbar caused the missing delivery.

The test now performs its already-required input and symbols-layer transition before the assertion helper that hides the IME and scrolls to the lower field. It still checks that Rune serves the multiline field, verifies the real symbols layer, changes to the plain editor, verifies the reset and typed `q`, then reads both editor texts. The redundant intermediate refocus is removed. No production code or keyboard policy changed.

The reordered method passed three direct instrumentation runs on a clean API 37 emulator and one on a clean API 26 emulator. Both temporary target AVDs were deleted. The main API 37 general run used the earlier test APK and retains its failure; these targeted passes do not convert that run into a pass. Both target AVD runs overlapped the continuing main emulator, so they are not timing evidence. Raw failure, diagnostic, build and pass logs are under `build/q7-api{26,37}-editor-*`; the isolated screenshot is retained only in `build/`. A complete fresh general run, Gradle-connected report verification and hosted CI are still needed.
