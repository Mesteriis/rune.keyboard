# Q7: API 37 composing-editor failure isolation

During the ongoing general API 37 direct-instrumentation run, five further cases failed after key input because `qa_composing_text` still exposed its empty-field hint instead of the expected text. Three cases cover flick/alternate entry and two cover theme changes; their assertions failed before establishing the requested editor text. The general run already had the separate editor-boundary failure and remains unsuccessful.

The same five methods were rerun on a separately created clean API 37 emulator with the same general fixture argument. The first and fifth passed in individual invocations, and the remaining three passed together in one instrumentation invocation; zero skips or failures were reported. The relevant flick, theme and shared-driver source files were unchanged between the original normal APK and these tests. The test APK also contained the separate editor-boundary test adjustment. Both emulators ran concurrently, so resource contention cannot be excluded, and the isolated results cannot replace a full-suite pass.

For one failed method, the captured hierarchy showed a focused empty composing EditText and exposed keyboard keys; its failure screenshot showed only the system bars and a blank content frame. A later live screenshot from the same emulator showed rendered settings. These observations do not establish whether a key event was delivered, why the frame was blank, or the cause of the suite-only failures. No speculative product or fixture change was made. Raw logs, hierarchy and synthetic emulator screenshots remain in `build/q7-api37-*`; the target AVD was deleted. The ongoing general run, a fresh full-suite rerun and hosted CI remain outstanding.
