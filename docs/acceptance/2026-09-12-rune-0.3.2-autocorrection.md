# Rune 0.3.2 — local autocorrection and Space-race acceptance

Date: 2026-09-12. Version code 5. This report covers the general distance-one
local policy, the asynchronous Space boundary and the diagnostics used to find
manual corrections. Model spelling keeps its previously qualified artifacts;
its quality was not recalibrated in this change.

## Observed problem and resulting behavior

The pre-update Fold logs and source replay showed that suitable candidates for
words such as `нескрлько`, `заьыл`, `прозрачныъ` and `резултат` could be found,
while correction was withheld because the model was unavailable, the extended
search exhausted its budget, or Space cancelled pending local work. The new
generator completes an exhaustive one-operation pass first and records its own
completion evidence. `LocalCorrectionPolicy` may use that completed result even
when the later extended search is incomplete.

For unknown words of at least five characters in lowercase, and in Russian
ordinary title case, the local policy now
uses the full distance-one candidate set before UI truncation. It replaces only
a sufficiently dominant active-language candidate. Ambiguous cases remain
suggestions. The original stays in the candidate strip, and all edits use the
existing owned-text transaction and exact Backspace Undo. Qualified local
decisions skip the model.

Space retains already scheduled local work for 250 ms. A late result may edit
only the unchanged Rune-owned `word + space`. A next character, Backspace,
cursor move, language/mode change, editor rejection or timeout invalidates it.
Cold lexicon completion resumes only the current matching session/revision and
does no candidate computation after the window. When local policy abstains, the
model receives only the remaining part of that same window.

An eligible text input view now starts validation of the dictionaries required
by its current language route before the first word ends. This warm-up contains
no editor text and is skipped for protected fields and disabled spelling. The
reviewed finite-confusion policy is version 2 and includes `заьыл → забыл` after
exact dictionary membership validation; the general five-letter RU threshold
was rejected because qualification measured only 96.7% precision.

## Dogfood evidence and diagnostics

Before installation, the Fold snapshot was copied to ignored
`build/dogfood/2026-09-12-pre-0.3.2/` with package, IME, display and system state,
all rotating diagnostics, preferences, logcat and the installed APK. SHA-256 is
recorded for every file. The installed 0.3.1 APK hash was
`cce686d4eb3a88afcd8bf5adb2d52d75aea8908c41fc8cadfa90aa338d9640e0`.

The snapshot contains 15,255 diagnostic events: 3,419 metadata and 11,836 text
events. Final-outcome analysis found 44 edits: 33 mechanical, seven automatic
replacements and four selected corrections; 38 remained applied and six were
undone. Three explicit Backspace events reconstructed two manual corrections,
including the anonymized three-letter `мкж` to `муж` regression. Historical
inference from text snapshots remains marked as tentative. Full message text
stays only in the ignored private snapshot.

Diagnostics schema 3 separates local and extended completion, inspected states,
verified terminals, policy/source codes, request schedule/submission/cancellation,
service failure and final word outcome. The analyzer continues to accept schema
1 and 2. A restored valid input session after a language or symbol-layer break
begins a new diagnostic segment while retaining consent and protected-field
exclusions.

## Scope limits

The change does not replace the model, add personalization or build a larger
dictionary index. Contextual punctuation remains off by default for new installs
and existing settings are preserved. The qualification covers the general local
branch independently; historical model evidence is not presented as fresh model
quality or device-latency evidence.
