## Spec and code assessment

- `ModelDemand.derive` is a pure cached-input predicate. A positive session, active/visible NORMAL text eligibility, READY hint and at least one enabled implemented model consumer are all required. Spelling and contextual demand are independent; disabled/unimplemented consumers cannot cause binding. No editor reads, storage/model resolution, load, network, or settings side effects enter derivation. The compatible Boolean entry point remains caller-owned; this proposal adds no real IME consumer. Its documentation correctly distinguishes a readiness hint and connected transport from a loaded/usable model.
- `LatestReplyGuard.kt:14–23` makes an identical normalized attachment a no-op. Demand OFF/ON and temporary null detach clear current reply ownership while retaining the same positive session's request watermark. `begin` rejects reused/out-of-order IDs, including after cancellation and reconnect. A different positive session resets the single retained watermark, under the documented requirement that owners assign distinct identities to genuinely different sessions; this is not an unbounded session-history registry.
- `BoundModelScoringClient.kt:39–47` cancels old work and tears down the prior registration only on an actual attachment change. The generation check after availability notification prevents listener reentry from causing an obsolete bind. Per-dispatch callbacks at lines 71–81 capture both generation and connection identity, then preserve full token/current revision validation. Retired callbacks cannot revive a session, including the adversarial recycled-token control. Guard/retry state retains numeric tokens rather than request text; reconnection does not replay requests.
- Lines 83–125 enforce three total attempts in one uninterrupted demand epoch, with 1000/2000 ms retry delays. Success, repeated attach, duplicate connection callbacks and request revisions do not replenish attempts. A stale timer cannot clear a newer timer: identity and generation are checked before mutation. A real demand edge or replacement session starts a fresh epoch. Close is terminal/idempotent and disabling/closing removes retries and releases registrations.
- Availability notification is transition-only and published state is updated before invoking the listener. False bind, SecurityException, null binding, binding death, disconnect and score RemoteException use the explicit registration cleanup/loss path. Connection retirement happens before unbind, so obsolete callbacks fail their identity check. Existing exception boundaries remain narrow; no broad catch hides programmer errors. All mutable adapter lifecycle work and reply evaluation remain on the main owner.
