## What looks correct

- **Process ownership and lazy entry.** `ProcessModelDuty.kt:7–8` creates the process singleton using elapsed realtime and `Process.getElapsedCpuTime`, not thread CPU. `ModelInferenceService.kt:25–26` obtains it before constructing the lazy adapter. The numeric owner contains no request, worker, observer, Service or Context reference. Lease acquisition is separate from credit admission; the worker retains its lease through warm/unloaded idle, serial close and final accounting. A contender without a lease cannot call score/unload/close, immediately rejects submitted work, and has no waiter or retry. Only a later explicit submit tries again. `LatestScoringWorker.kt:109–121` releases the lease in final cleanup, including recoverable cleanup failure; an obsolete lease cannot release a successor.
- **Sampled accounting.** `ModelDutyOwner.kt:44–66` serializes all observations, refills then caps before debiting the newly observed whole-process CPU interval. Fifteen units per CPU millisecond and two per elapsed millisecond preserve the declared fractional refill. Admission uses post-debit credit at least 112500 units; active cancellation uses credit at or below zero. Negative debt persists. Backward, negative or throwing samples permanently fault the owner, prevent refill/admission, and still allow later valid CPU increments to be charged. Overflow saturates rather than wrapping or granting new credit. Service/worker/session changes do not reset the owner baseline or debt.
- **Bounded request ownership.** The worker retains one active and one replacing pending request. Receipt is sampled before the worker monitor, and replacing a pending request with the same session/request identity preserves its earliest timestamp. Queue admission rejects age at least 3000 ms. A denied newer request still cancels the old active request and finishes the replaced pending request; it is not parked for credit recovery. The original `ScoringInput`, ordered candidate IDs and full candidate set reach the engine unchanged.
- **Watchdog and lock ordering.** Operation identity, flag-setting and `engine.cancel` are checked under the worker monitor, so a retired timer cannot cancel a replacement operation. The flag is set first. The numeric owner lock is not held across engine/native calls or waits; pressure releases that lock before taking the worker monitor. The unchanged watch callback holds its own callback lock before invalidation, while worker-monitor paths still do not acquire that watch lock: score/unload/close run outside the monitor, and cancellation uses the nonblocking runtime seam. Timer retirement precedes the next operation, cancellation does not join the timer or native work, and final score sampling rejects a fast overshoot even before the first periodic check.
- **Cleanup, cancellation and idle.** Cleanup operations have no cancellation flag; their timer only accounts CPU, including under debt/fault. Ordinary revision cancellation does not request unload, retaining the already-reviewed warm-adapter behavior. Compulsory invalidation/unload/close remains serial after active exit. `Work.finish` is guarded exactly once, including replacement, denial, expiry, cancellation, close and recoverable engine/delivery/finished exceptions. The request frame returns before subsequent idle waits; denied work does not reset the idle timestamp. The 60-second one-time idle unload remains, with no periodic duty timer during idle/unloaded waits.
- **Pressure and lifecycle.** Suspension and generation advancement happen before acquiring the worker monitor. Revisions, submits, duplicate binds and model invalidation cannot clear the latch. Rearm requires the current numeric lifecycle and a prior actual unbind; obsolete lifecycle callbacks cannot rearm a successor. Debt and retiring-lease ownership remain intact. Later pressure again suspends admission. Production `onUnbind` stays false, invalidates work and blocks submissions until bind resumes.
