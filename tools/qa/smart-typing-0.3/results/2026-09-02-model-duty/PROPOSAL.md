# Service CPU duty implementation proposal

Parent proposal after the fixed physical Fold runtime baseline; not an energy qualification or selected release budget. No new benchmark/holdout run. Current active client implementation is separate.

Implement service-side controls before any IME model consumer is enabled. Keep one active plus one replacing pending request and unchanged serial teacher forcing/candidate counts. A denied/stale/cancelled request yields no usable scores; deterministic/original fallback remains immediate at editor boundaries.

Development profile for a predeclared trace experiment: token-bucket capacity8000 process-CPU ms, refill8000 per60000 elapsed ms, initial credit8000, require at least7500 CPU ms credit to admit a new speculative call. No burst accumulation above capacity. A call's process CPU is charged continuously through active checks and on finalization, including resolve/watch/load/score/revalidation and failure/cleanup. Required unload/close always executes and incurs debt. This is a nominal sampled token-bucket admission/cancellation policy, NOT an exact execution/burst ceiling, strict rolling8000ms cap or measured battery budget. Mandatory cleanup and cooperative cancellation may overshoot; report debt/overshoot separately. It may retain debt below zero rather than forgive cleanup cost. The7500 minimum avoids starting on a tiny remaining allowance while explicitly tolerating up to500 CPU ms of entry/idle-process debit at a recovered8000 cap. This500 is an experimental accounting tolerance, not measured overhead. Cold/long RU8 requests can cancel sooner when admitted below8000; smaller measured requests recover credit sooner. No payload/candidate-count truncation to fit the budget.

Reasons for this experimental profile: fixed Fold RU8 p95 processCPU7656ms, max request wall2074ms; cold load observed355CPU/360wall, unload100CPU/101wall. 8000CPU burst and3000ms active wall deadline are conservative engineering hypotheses around that baseline, not proved coverage for service/production text. RU8 cold or long-tail requests can still be cancelled. 50ms active-only control checks sample Process.getElapsedCpuTime and monotonic elapsed time, set the request AtomicBoolean before engine.cancel, and stop immediately when no active engine/cleanup work remains. CPU checks cannot guarantee an exact stop bound because native cancellation is cooperative. No timer when idle/unloaded;60s idle unload remains once, denied work does not reset it.

Use a named process-lifetime numeric duty owner scoped to :model_runtime, surviving Service/worker recreation. It retains no input/candidate/Service/Activity/Context. Guard lazy engine entry with an owner/lease identity, retained through warm idle ownership and all retirement/final close. A new worker receives immediate UNAVAILABLE/no scores while an old lease/cleanup is held; no waiter queue, spontaneous retry or second runtime. Release once after completed close/final accounting, including exceptional teardown. No lock held across native waiting or joining. A real process restart, unlike Service recreation, may grant the one initial bounded credit.

Use fixed primitive numeric gate state, saturating/overflow-safe arithmetic and injected monotonic wall/processCPU source for deterministic tests. Arithmetic: under the numeric owner lock, calculate nonnegative elapsed/CPU deltas, refill prior credit and cap at8000, then debit all newly observed processCPU. Preserve fractional refill exactly (for example fifteen fixed units per CPU ms and two per elapsed ms); do not discard carry on50ms subdivisions. Saturate without wrapping or minting credit. Admission uses the post-debit credit>=7500; active exhaustion remains credit<=0. Values499/500/501CPU ms debit after long-idle cap must respectively admit/admit/deny. Invalid/backward/missing/throwing CPU/wall samples permanently fault the numeric owner until actual process restart: cancel/deny speculative work, preserve debt and do not establish a new full baseline; compulsory cleanup still runs. Charge all processCPU since the previous accounted sample conservatively, even if another service thread/GC contributes. Serialize monitor/admission/finalization/cleanup samples so each observed processCPU interval is charged once. Reconnect/session/revision/Service recreation never resets the process-lifetime owner. Process recreation can grant only one initial bounded credit; the bounded client prevents unlimited reconnect loops, but this is not proof against arbitrary external repeated process kills. Do not persist user payload or CPU history to disk.

Latest pending replacement is bounded and carries only its existing input until active completion/admission. Denied work finishes immediately with existing UNAVAILABLE/no scores; it does not schedule a retry or remain queued until credit returns. Expiry uses receipt monotonic timestamp; choose an explicit3000ms maximum queue age for this development experiment (separate from3000ms active deadline), reject at admission, and never extend age by pending replacements of the same request. Runtime request tokens remain caller-monotonic; service token validation is unchanged. Binder cancel must remain nonblocking and cannot wait for score/CPU-monitor joins.

Memory pressure: critical/background/low-memory calls first atomically latch process-owner admission suspended and advance the lifecycle generation, then drop pending work, set the active cancellation flag/signal and schedule serial unload. New submits/revisions cannot clear the latch. Only a genuinely later onBind lifecycle after prior onUnbind may rearm, retaining numeric debt and respecting any retiring lease; preserve current onUnbind returnfalse. Extra bind callbacks/revisions/model invalidation cannot rearm. Concurrent later pressure wins over an earlier rearm. Do not automatically poll memory or reload after trim. Model version invalidation cancels/unloads but neither sets nor clears the critical-memory latch. Close is terminal. Unload/close must run serially after active exit, even when gate exhausted or clock invalid.

Watchdog transitions: check operation/lease identity, set its AtomicBoolean and call nonblocking engine.cancel atomically against worker replacement; retire timer identity before another request. Avoid inverse lock ordering with worker/watch callbacks. Late timers are no-ops. Request load/score may be cancelled; compulsory unload/close is uncancellable, with final CPU accounting (any cleanup monitor only samples). No main/Binder joins. Every replaced/denied/expired/cancelled/failed/closed work calls its finished death-recipient cleanup exactly once, including throwing engine/clock/callback paths.

Minimum tests before integration: old Service retirement held through close while a new worker is denied, debt preserved and no overlap/retry after release; warm-idle retirement; exceptional teardown lease release; trim/submit/rearm races; long idle plus499/500/501CPU debit and fractional subdivision invariance away from capacity saturation; gate refill/cap/debt/invalid-clock/overflow; nonzero processCPU charged despite zero caller-threadCPU; cancelled/failed/cold/resolver-only work charged; denied requests never call engine or extend idle; exact only-active watchdog lifetime and stale-token timer safety; wall/CPU cancel flags observed before engine.cancel; normal revision cancellation retains warm engine; complete cleanup in debt/clockfailure; pending replacement and expiry; memory suspension until real new bind lifecycle; session/binder churn retains duty accounting. Exercise actual LatestScoringWorker with controlled clock/engine, not only a standalone bucket. Add actual service synthetic Binder lifecycle fixture for pressure/rearm as needed.

Qualification: replay fixed public synthetic traces with2/4/8 candidates in eachlanguage, rapid typing, stable pauses, idle, cancellation, failed load and memory pressure. Report admitted/denied/expired/cancelled/completed/usable-before-boundary separately, processCPUwall and cancellation overshoot; never infer battery savings from counters alone. OrdinaryCI uses synthetic engine/clocks; exactrealmodel digest required for physical. All profile constants are recorded and frozen before that trace run; subsequent changes require separate trace evidence, not deletion of bad runs. Model quality/calibration gates and phone energy remain independent and open.
